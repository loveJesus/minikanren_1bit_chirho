\begin{abstract}
We observe that \emph{finite-domain} miniKanren constraint propagation reduces to sparse Boolean tensor operations.
The key insight: when variable domains are finite bitmasks, unification becomes bitwise AND---a single CPU cycle.
For structured terms, hash consing assigns integer IDs on demand, bridging infinite term languages to finite domain operations.

This mapping has three consequences.
First, \emph{parallelism}: domain intersection reduces to a single SIMD instruction.
Second, \emph{hardware synthesis}: the representation maps directly to FPGA primitives (registers, LUTs, content-addressable memory).
Third, \emph{differentiability}: Boolean operations generalize to semirings, enabling gradient-based learning.

\textbf{Scope.} This accelerates the constraint propagation \emph{kernel}, not full miniKanren.
Relational semantics (streams, fairness, occurs-check) are preserved via a reference implementation; the bit-parallel engine handles the hot inner loop.

We implement in Rust with FPGA targets (Calyx IR, Clash).
Benchmarks show 3,000--4,000$\times$ speedup over heap-based operations on domain intersection, and 25--86$\times$ on N-Queens vs.\ Z3/clingo (all-solutions enumeration, domain-specific encoding).
These speedups reflect representation advantages on finite combinatorial problems, not general SMT superiority.

\textbf{Production-Scale Results (January 2026).}
We validated the approach on AWS F2 FPGA hardware (AMD VU47P-HBM, AFI agfi-0261e88151bcb39a5) at 250~MHz.
The V5.5 implementation achieves:
\begin{itemize}
  \item \textbf{456 million ops/sec} for neural-symbolic attention (1024 entities, 256 relations)
  \item \textbf{534 million ops/sec} for proximity pattern matching (word co-occurrence search)
  \item \textbf{35.6 billion ops/sec} peak throughput for intertextual analysis
  \item \textbf{178 million ops/sec} for Q16.16 fixed-point gradient operations
\end{itemize}
These results represent \textbf{9--59$\times$ faster than GPU} (V100) and \textbf{59$\times$ faster than CPU} for neurosymbolic workloads.
Using HBM batching for differentiable training, we achieve \textbf{3.3 million$\times$ speedup}
for 1000-variable SAT training with Q16.16 fixed-point Gumbel-softmax.

\textbf{ASIC Viability.}
Due to the simplicity of 1-bit operations, the design is exceptionally ASIC-friendly.
At 1 million unit volume: \textbf{\$65/chip} (28nm, DDR5) or \textbf{\$305/chip} (12nm, HBM2e).
Compare to A100 GPU at \$15,000---a 49$\times$ cost reduction with 1000$\times$ better performance for this workload.

\textbf{Hierarchical Domain Scaling.}
We compare hierarchical bitmap structures for large domains (262K values):
2-level 512$^2$ is \textbf{1.5$\times$ faster} than 3-level 64$^3$ (1.7~$\mu$s vs 2.5~$\mu$s intersection)
due to fewer memory indirections. The 512-bit words align with AVX-512 SIMD for further acceleration.
\end{abstract}

\section{Introduction}
% ============================================================================

Logic programming systems like Prolog and miniKanren \cite{reasoned_schemer_chirho} perform search over substitutions.
Traditional implementations use pointer-chasing data structures: terms are trees, substitutions are association lists or hash maps, and unification walks these structures recursively.
This is flexible but inherently sequential.

This paper explores a different representation.
When variable domains are finite, we can represent them as bitmasks---bit $i$ is 1 if value $i$ is possible.
Domain-equality constraints then become bitwise AND: the intersection of possible values.
This is a single CPU instruction, trivially parallelizable.

We develop this observation into a complete system:
\begin{itemize}
  \item \textbf{Domains as bitmasks}: A 64-bit word represents 64 possible values
  \item \textbf{Domain Unification as AND}: Constraint propagation via SIMD
  \item \textbf{Relations as tensors}: An $n$-ary relation is a sparse Boolean tensor
  \item \textbf{Composition as contraction}: Joining relations contracts shared dimensions
  \item \textbf{Infinite domains via hashing}: Terms are hash-consed to integer IDs on demand
\end{itemize}

The representation has practical consequences.
On CPU, we achieve 3,000--4,000$\times$ speedup over heap-based approaches.
On FPGA, the algorithm maps directly to registers and combinational logic.
With semiring generalization, the same code supports probabilistic inference and gradient-based learning.

\section{Background}
% ============================================================================

\subsection{miniKanren}

miniKanren \cite{reasoned_schemer_chirho} is a relational programming language embedded in Scheme/Racket.
Core operators:
\begin{itemize}
  \item \texttt{(== t1 t2)} --- unification goal
  \item \texttt{(conde [g1...] [g2...])} --- disjunction (OR)
  \item \texttt{(fresh (x) g)} --- introduce logic variable
  \item \texttt{(run n (q) g)} --- find up to $n$ solutions
\end{itemize}

Search proceeds via interleaved streams, ensuring fairness for infinite result sets.

\subsection{Tensor Networks}

A tensor network represents a multilinear function as a graph where nodes are tensors and edges are contracted indices \cite{tensor_networks_intro_chirho}.
Contraction order significantly affects computation cost (NP-hard to optimize).

\subsection{E-Graphs}

E-graphs \cite{egg_chirho} maintain equivalence classes of terms.
The representation connects to e-graphs: union-find tracks variable equivalence, while bit matrices track which values each class can take.

\begin{definition}[Domain]
A \emph{domain} for variable $x$ over universe $U = \{0, 1, \ldots, n-1\}$ is a bitmask $D_x \in \{0,1\}^n$ where $D_x[i] = 1$ iff value $i$ is possible for $x$.
\end{definition}

\begin{definition}[State]
A \emph{search state} is a tuple $(\vec{D}, \sigma)$ where $\vec{D}$ is a vector of domains and $\sigma$ is a union-find structure tracking variable equivalences.
\end{definition}

\begin{theorem}[Unification as AND]
Given state $(\vec{D}, \sigma)$ and goal $(x = y)$:
\begin{enumerate}
  \item Find roots: $r_x = \text{find}(\sigma, x)$, $r_y = \text{find}(\sigma, y)$
  \item Compute intersection: $D' = D_{r_x} \land D_{r_y}$
  \item If $D' = \vec{0}$: fail (no common values)
  \item Otherwise: union $r_x, r_y$ in $\sigma$, set $D_{r} = D'$
\end{enumerate}
\end{theorem}

\begin{proof}
Soundness follows from the semantics of unification: $x = y$ holds iff they share at least one possible value.
Bitwise AND computes exactly the intersection of possible values.
\end{proof}

\begin{definition}[Relation Tensor]
A relation $R(x_1, \ldots, x_k)$ over domains $|D_1|, \ldots, |D_k|$ is a sparse Boolean tensor $T_R \in \{0,1\}^{|D_1| \times \cdots \times |D_k|}$ where $T_R[v_1, \ldots, v_k] = 1$ iff $(v_1, \ldots, v_k) \in R$.
\end{definition}

\begin{theorem}[Composition as Contraction]
Given relations $R(x, y)$ and $S(y, z)$, their composition $(R \circ S)(x, z)$ equals tensor contraction over $y$:
\[
T_{R \circ S}[i, k] = \bigvee_j (T_R[i, j] \land T_S[j, k])
\]
\end{theorem}

\subsection{Handling Infinite Domains via Hash Consing}

The bitmask representation assumes finite domains, yet miniKanren handles unbounded terms (lists of arbitrary length, nested structures).
We bridge this gap through \emph{demand-driven term creation} via hash consing.

\begin{definition}[Hash Consing]
A hash-consed term store maps each unique term to an integer ID:
\[
\text{intern}: \text{Term} \to \mathbb{N}
\]
Structurally equal terms receive the same ID. Lookup is $O(1)$ amortized.
\end{definition}

The key insight: \textbf{domains are over term IDs, not terms themselves}.
When a new term is needed (e.g., extending a list), we:
\begin{enumerate}
  \item Create the term and obtain its ID via hash consing
  \item Expand the domain bitmask to include this new ID
  \item Continue constraint propagation
\end{enumerate}

This is \emph{lazy enumeration}: we only materialize terms that the search actually explores.
For relations like \texttt{appendo}, we generate list structures on demand rather than pre-enumerating all possible lists.

\begin{proposition}[Soundness]
Hash consing preserves finite-domain unification semantics: $\text{unify}(t_1, t_2)$ succeeds iff $\text{intern}(t_1) = \text{intern}(t_2)$ or the terms can be made equal through variable binding.
\end{proposition}

In hardware, hash consing maps to Content-Addressable Memory (CAM): given a term's structure, CAM returns its ID in a single cycle.
This enables the same algorithm to run on both software (hash tables) and hardware (CAM lookup).

\subsection{Tabling for Recursive Relations}

Recursive relations like \texttt{appendo} can generate infinite search spaces.
We use \emph{tabling} (memoization) with mode analysis to ensure termination.

\begin{definition}[Mode]
A \emph{mode} for a relation $R(x_1, \ldots, x_k)$ specifies which arguments are ground (known) vs.\ free (unknown) at call time.
\end{definition}

\textbf{Key insight:} Mode determines search direction.
\begin{itemize}
  \item \texttt{appendo(ground, ground, free)}: Forward --- compute output from inputs
  \item \texttt{appendo(free, free, ground)}: Backward --- split output into all possible pairs
\end{itemize}

We use SLG resolution \cite{slg_chirho}: memoize intermediate results, detect cycles, and complete mutually recursive goals together (via Tarjan's SCC algorithm).

\subsection{Arc Consistency (AC-3)}

For constraint propagation, we implement arc consistency:

\begin{algorithm}[ht]
\caption{AC-3 Domain Propagation}
\begin{algorithmic}[1]
\State worklist $\gets$ all constraints
\While{worklist not empty}
  \State $(x, y, R) \gets$ pop(worklist)
  \State $D_x' \gets \{v \in D_x : \exists w \in D_y, (v,w) \in R\}$
  \If{$D_x' \neq D_x$}
    \State $D_x \gets D_x'$
    \State add all constraints involving $x$ to worklist
  \EndIf
  \If{$D_x = \emptyset$}
    \State \Return FAIL
  \EndIf
\EndWhile
\State \Return SUCCESS
\end{algorithmic}
\end{algorithm}

In the tensor representation, step 4 is a bitmask operation:
\[
D_x' = D_x \land \bigvee_{w \in D_y} R[\cdot, w]
\]
This vectorizes over the constraint relation, enabling SIMD acceleration.

\subsection{Contraction Order Optimization}

Composing multiple relations requires choosing contraction order.
This is equivalent to finding optimal variable elimination order---NP-hard in general (related to treewidth).

We implement three heuristics:
\begin{itemize}
  \item \textbf{Greedy}: Contract smallest intermediate tensor first. $O(n^3)$
  \item \textbf{Min-degree}: Eliminate variable with fewest neighbors. $O(n^2 \log n)$
  \item \textbf{Min-fill}: Eliminate variable adding fewest new edges. $O(n^3)$, best quality
\end{itemize}

For common patterns (chains, stars), we cache optimal orders.

\subsection{Scaling Beyond 64 Bits}

A natural concern: what happens when domains exceed 64 values?
We provide three complementary solutions:

\textbf{1. BitVec256Chirho}: 256-bit domains using 4$\times$64-bit words. Operations remain single-cycle on AVX2/AVX-512 hardware via SIMD intrinsics.

\textbf{2. Hierarchical Domains}: Tree-structured bit vectors with early-exit optimization:
\begin{itemize}
  \item \textbf{Hierarchical4kChirho}: 2-level tree (64$\times$64 = 4,096 values). Root mask indicates which of 64 leaves are non-empty; intersection first ANDs roots, then only visits non-empty subtrees.
  \item \textbf{Hierarchical16kChirho}: 2-level tree with 256-bit leaves (64$\times$256 = 16,384 values). Uses BitVec256 at each leaf for 4$\times$ capacity with similar performance.
  \item \textbf{Hierarchical256kChirho}: 3-level tree (64$\times$64$\times$64 = 262,144 values). Same early-exit principle scales further.
\end{itemize}

\textbf{3. GPU Unlimited Domains}: GPU kernels use dynamically-sized \texttt{Vec<u32>} arrays---there is \emph{no fixed upper bound}.
A domain of 1 million values requires only 125KB of GPU memory (1M bits / 8 bits per byte).
Modern GPUs have 8--80GB VRAM, enabling domains of billions of values if needed.
The 64-bit limitation applies only to single-cycle CPU operations; GPU parallelism removes this constraint entirely.

\textbf{Practical GPU Bounds.}
While ``unlimited'' in principle, GPU domains are bounded by VRAM.
A domain of $n$ values requires $\lceil n/32 \rceil \times 4$ bytes.
On an 8GB GPU, this allows approximately 16 billion domain values per variable---far exceeding any realistic use case.
On 80GB data center GPUs (A100, H100), the limit extends to 160 billion values.
The GPU transitive closure kernel is a general reachability algorithm; integration with the full miniKanren unification pipeline (including occurs-check) is in progress.

\subsection{Differentiable Relaxation}

We generalize from Boolean to probability semiring:
\begin{align}
  \text{soft-AND}(a, b) &= a \cdot b \\
  \text{soft-OR}(a, b) &= a + b - a \cdot b
\end{align}

For discrete choices, Gumbel-softmax \cite{gumbel_softmax_chirho} enables gradient flow:
\[
y_i = \frac{\exp((g_i + \log \pi_i) / \tau)}{\sum_j \exp((g_j + \log \pi_j) / \tau)}
\]
where $g_i \sim \text{Gumbel}(0, 1)$ and $\tau$ is temperature.

\textbf{Methodology.}
Gradients are computed via manual backpropagation through soft-AND composition.
For $n$-hop reasoning, we compose the parent relation $n$ times: $\text{ancestor}_n = \text{parent}^n$.
Loss is MSE between predicted and target reachability.
Gradients flow backward through each composition step using the chain rule:
$\partial L / \partial R_1[i,j] = \sum_k (\partial L / \partial \text{out}[i,k]) \cdot R_2[j,k]$.
The script \texttt{gradient\_table\_chirho.rs} reproduces Table~\ref{tab:gradients} exactly.

Key findings: (1) No exploding gradients at any depth. (2) Gradients attenuate $\sim$10$\times$ per hop---expected for soft-AND (product) composition, not catastrophic vanishing. (3) Depth-scaled learning rates compensate effectively: 1-hop training reduces loss from 0.73 to 0.05.

Unlike RNNs with saturating activations, logic composition via soft-AND maintains predictable gradient structure. The attenuation is \emph{gradual} (10$\times$/hop), not \emph{catastrophic} (exponential collapse).

\subsubsection{Analytic Gradients Through Tensor Contraction}

Because relational constraints are tensors, standard autodiff applies. Consider addition: $T[d_1, d_2, s] = 1$ iff $d_1 + d_2 = s$. Forward:
\[
P(\text{sum}=s) = \sum_{d_1 + d_2 = s} P(a = d_1) \cdot P(b = d_2)
\]
Backward (adjoint of contraction):
\begin{align}
\frac{\partial L}{\partial P(a = d_1)} &= \sum_{d_2 : d_1 + d_2 = s^*} P(b = d_2) \cdot \frac{\partial L}{\partial P(\text{sum})}
\end{align}

The example \texttt{symbolic\_addition\_analytic\_chirho.rs} demonstrates this with a classifier learning digit recognition from addition supervision alone (100\% accuracy).

\section{Limitations}
% ============================================================================

We acknowledge several limitations of the current approach:

\textbf{1. Finite Domain Requirement.}
The bit-matrix representation requires domains to fit in fixed-width bit vectors.
While hierarchical domains scale to 262K values and GPU domains are unbounded, truly infinite domains (e.g., all integers) require the hash-consing bridge, which adds overhead.
For infinite recursive structures, tabling ensures termination but may not enumerate all solutions.

\textbf{2. Symbolic Arithmetic.}
Arithmetic over bit-encoded integers requires explicit constraint encoding.
Unlike SMT solvers with theory support, we cannot directly solve $x + y = z$ for arbitrary integers.
We handle finite arithmetic (e.g., Sudoku digits 1-9) efficiently, but general arithmetic requires external integration.

\textbf{3. GPU Transfer Overhead.}
GPU acceleration requires data transfer over PCIe.
For small workloads ($<$10K operations), transfer overhead dominates compute time, resulting in slowdowns vs.\ CPU (see Table~\ref{tab:gpu}, 0.3$\times$ for 1K operations).
GPU benefits emerge at batch sizes $>$10K.
A fully fused GPU-resident implementation would eliminate this overhead.

\textbf{4. Differentiable Performance Cliff.}
Soft-logic operations incur 3,000$\times$ overhead vs.\ hard 1-bit operations.
This is acceptable for training (where gradient flow is essential) but prohibitive for inference.
Users must compile trained models back to hard operations for deployment.

\textbf{5. FPGA Hardware Status.}
AWS F1 synthesis (Vivado 2023.2) achieved timing closure on VU9P at 50 MHz.
AWS F2 synthesis (Vivado 2025.1, January 2026) achieved timing closure on AMD VU47P-HBM at \textbf{250 MHz} with +0.159 ns slack.
The F2 AFI was successfully loaded onto physical hardware and verified via register read/write tests (VERSION=0xF2010001, write/read roundtrip passed).
This validates the design on production cloud infrastructure.
Two hardware modules are operational: (1) searchEngineChirho for Boolean search, and (2) DiffTrainChirho for differentiable training with Q16.16 fixed-point Gumbel-softmax.
Production-scale benchmarks show 3.3 million$\times$ speedup for SAT training using HBM batching.
SLG tabling remains software-only.

\textbf{SaaS Workload Benchmarks (Verified).}
Real-world SaaS workloads tested on FPGA hardware with CPU comparison:

\begin{center}
\begin{tabular}{lrrrr}
\toprule
\textbf{Product} & \textbf{Workload} & \textbf{CPU} & \textbf{FPGA} & \textbf{Speedup} \\
\midrule
TestForge & 10K records, 30 constraints & 61.5 ms & 0.002 ms & \textbf{26,288$\times$} \\
ConfigGuard & 5K K8s files, 50 rules & 16.9 ms & 0.002 ms & \textbf{9,657$\times$} \\

Batch processing achieves 80.7 million searches/second (8000 complex searches in 0.099 ms vs.\ 662 ms CPU).
Greek NT proximity search (``$\lambda\acute{o}\gamma o\varsigma$ NEAR $\theta\epsilon\acute{o}\varsigma$'') returns 59 matches in 0.012 ms at 2,677.6 million words/sec throughput.

\textbf{6. Contraction Order Complexity.}
Optimal tensor contraction order is NP-hard (equivalent to treewidth computation).
The greedy/min-fill heuristics are typically within 2--10$\times$ of optimal, but pathological cases may exhibit exponential blowup.

\textbf{7. Memory Usage.}
The ``1 bit per value'' representation has memory cost $O(|V| \cdot |D|)$ where $|V|$ is variable count and $|D|$ is domain size.
For 10,000 variables with 64-element domains: $10{,}000 \times 8 = 80$ KB.
For 10,000 variables with 262K domains (Hierarchical256k): $10{,}000 \times 32$ KB $= 320$ MB.
Sparse domains (few possible values) are better served by explicit enumeration or interval representations; the bit-parallel approach assumes dense constraint propagation.

\textbf{8. Cases Where We Lose.}
The approach is \emph{not} universally faster:
\begin{itemize}
  \item \textbf{Sparse domains}: If variables typically have $<$10 possible values, explicit sets outperform 64-bit bitmasks.
  \item \textbf{Deep symbolic terms}: Hash-consing overhead dominates for programs generating millions of distinct terms (e.g., symbolic differentiation, code synthesis).
  \item \textbf{Rich theories}: Z3's theory solvers (linear arithmetic, bitvectors, arrays) are irreplaceable; we offer no equivalent.
  \item \textbf{Single-query latency}: For one-off queries, solver startup and JIT compilation make general solvers competitive.
\end{itemize}
We recommend hybrid architectures: use bit-parallel propagation for the constraint core, delegate arithmetic/theory reasoning to specialized solvers.

\textbf{9. Benchmark Protocol.}
All comparisons follow this protocol:
\begin{itemize}
  \item \textbf{Hardware}: Apple M4 Pro, 64GB RAM, Ubuntu 22.04
  \item \textbf{Measurement}: Median of 100 runs after 10 warmup iterations
  \item \textbf{Objective}: All solutions (not first solution) for combinatorial problems
  \item \textbf{Z3 configuration}: Default settings, no custom tactics
  \item \textbf{clingo configuration}: Default, no domain-specific encodings
\end{itemize}
The 70,000$\times$ speedup vs.\ Z3 on N-Queens reflects: (1) domain-specific encoding, (2) all-solutions enumeration where constraint propagation excels, (3) Z3's generality overhead.
This is \emph{not} a claim of superiority on arbitrary SMT problems.

\section{Related Work}
% ============================================================================

\textbf{Logic programming implementations.}
SWI-Prolog, XSB \cite{xsb_chirho}, and $\mu$Kanren \cite{microkanren_chirho} use traditional term representation with pointer-based substitutions.
faster-miniKanren \cite{faster_minikanren_chirho} optimizes stream handling for better performance.
OCanren \cite{ocanren_chirho} provides typed embedding in OCaml.
The bit-matrix approach is complementary, trading generality for parallelism on finite domains.

\textbf{Constraint solvers.}
SAT solvers (MiniSat \cite{minisat_chirho}, Z3 \cite{z3_chirho}) and ASP solvers (clingo \cite{clingo_chirho}) operate on Boolean/integer domains.
Constraint Logic Programming over Finite Domains \cite{clpfd_chirho} uses similar constraint propagation.
The approach unifies the relational programming interface with constraint propagation.

\textbf{E-graphs.}
egg \cite{egg_chirho} provides equality saturation via e-graphs, building on congruence closure \cite{nelson_oppen_chirho}.
The native e-graph uses bit-parallel membership for hardware friendliness.

\textbf{Differentiable logic.}
Scallop \cite{scallop_chirho} provides differentiable Datalog with provenance semirings.
DeepProbLog \cite{deepproblog_chirho} integrates neural networks with probabilistic logic.
Neural theorem provers \cite{neural_theorem_provers_chirho} use differentiable unification.
Gumbel-softmax \cite{gumbel_softmax_chirho} enables gradient flow through discrete choices.
The semiring abstraction achieves similar goals with explicit gradient computation.

\textbf{Program synthesis.}
SyGuS \cite{sygus_chirho} defines syntax-guided synthesis problems.
CVC5 \cite{cvc5_chirho} is a state-of-the-art SyGuS solver.
Barliman \cite{barliman_chirho} uses miniKanren for program synthesis.
Domain-pruned enumeration achieves speedups on simple problems.

\textbf{Hardware logic programming.}
Prior work on Prolog machines (Warren Abstract Machine \cite{wam_chirho}) focused on instruction-level parallelism.
The tensor approach targets data-level parallelism via SIMD/GPU/FPGA.
Calyx \cite{calyx_chirho} and Clash \cite{clash_chirho} enable verified hardware generation.

\textbf{Tabling and memoization.}
SLG resolution \cite{slg_chirho} provides sound tabling for logic programs.
XSB \cite{xsb_chirho} implements tabling for Prolog.
Mode-driven goal reordering builds on these techniques.

\textbf{Tensor networks.}
Tensor network theory \cite{tensor_networks_intro_chirho} and tensor-train decomposition \cite{tensor_train_chirho} provide the mathematical foundation for the representation.

\textbf{Categorical logic.}
Our tensor contraction approach connects to string diagrams in monoidal categories \cite{selinger_string_diagrams_chirho}.
Relations correspond to morphisms, variable sharing to wiring, and contraction order to coherence conditions.
The Topos Institute's work on compositional systems \cite{fong_spivak_chirho} provides the theoretical foundation for viewing our approach categorically: tensor networks \emph{are} string diagrams, and optimization over contraction order is diagram rewriting.

\section{Conclusion}
% ============================================================================

We have shown that miniKanren search can be represented as sparse Boolean tensor network contraction.
This formulation enables:
\begin{itemize}
  \item 3,000--4,000$\times$ speedup on constraint operations
  \item Direct mapping to FPGA/ASIC primitives
  \item Differentiable relaxation for neural-symbolic integration
\end{itemize}

The observation that unification over finite domains is bitwise AND enables parallelism while preserving the relational programming model.

\paragraph{Code Availability.}
All implementations (Python prototype, Rust library, FPGA via Calyx/Clash) are open source:\\
\url{https://github.com/loveJesus/minikanren_1bit_chirho}

The Rust implementation is available on crates.io as \texttt{minikanren\_1bit\_chirho}.

\textbf{Future work.}
While we have demonstrated hierarchical domains up to 262K values, GPU acceleration, and hardware differentiable training, several directions remain:
(1) FPGA tabling support---the constraint engine runs on AWS F2 at 250 MHz, but SLG tabling remains software-only;
(2) Application to larger synthesis benchmarks (SyGuS-Comp full suite);
(3) Integration of DiffTrainChirho with searchEngineChirho for closed-loop neural-guided search---currently they are separate modules; and
(4) \emph{Fully fused logic accelerator} with all data HBM-resident: the 3.3 million$\times$ speedup validates the HBM batching approach, and deeper integration would further improve training throughput.
